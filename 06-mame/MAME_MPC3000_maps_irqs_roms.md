### FDC high byte

The comment above `fdc_hc365_r` says:

- bit 0 = ED, 1 if the disk was not ejected before the last check
- bit 1 = `/EDD` (enhanced density if 0, DD/HD if 1)
- bit 2 = `/HDD` (high density if 0, double density if 1)
- bits 3 and 4 = footswitches

The function returns `floppy_is_hd() ? 0x04 : 0`, ORed with `dskchg_r()`. It does not implement bits 1, 3, or 4.

## DMA

CPU memory DMA callbacks read and write the V53 program space. The 16-bit callbacks shift the offset left by 1 before the word access. `out_hreq_cb` is wired to the CPU's own `hack_w`. `out_eop_cb` is input 0 of an `INPUT_MERGER_ALL_HIGH` named `tc`, whose output is the FDC `tc_line_w`. No second input of that merger is set in this file.

| Channel | Wired in `mpc3000()` | Header comment |
|---|---|---|
| 0 | SCSI `dma_r` / `dma_w`, DREQ from MB89352 | SCSI |
| 1 | FDC `dma_r` / `dma_w`, DREQ from uPD72069 | floppy |
| 2 | not connected | IC31, "some sort of direct-audio stream?" |
| 3 | DSP `dma_r16_cb` / `dma_w16_cb`, DREQ from the DSP | L7A1045 |

## IRQ

Timer outputs 0, 1, and 2 call `INPUT_LINE_IRQ0`, `IRQ1`, and `IRQ2` on the V53.

| Line | Wired in `mpc3000()` | Header comment |
|---|---|---|
| IRQ3 | `intp3` (`INPUT_MERGER_ANY_HIGH`): FDC `intrq` is input 0, SCSI IRQ is input 1 | wire-OR of uPD72069 and MB89352 |
| IRQ4 | `intp4` (`ANY_HIGH`): TE7774 `txrdy` handlers 0–3 | wire-OR of all four TXRDY |
| IRQ5 | `intp5` (`ANY_HIGH`): TE7774 `rxrdy` handlers 0–2 | wire-OR of RXRDY1, 2, and 3 |
| IRQ6 | not connected | SMPTE sync in |
| IRQ7 | TE7774 `rxrdy` handler 3, direct | RXRDY4 |

Handler index 0 is the first UART channel in this file. The header's RXRDY1 aligns with handler 0 only if the header counts from 1.

## MIDI and panel serial

Wired:

- MIDI in port RXD goes to TE7774 `rx_w<0>` only.
- TE7774 `txd_handler<0>` goes to the single MIDI out port.
- Panel `txd_func` goes to TE7774 `rx_w<2>` and `rx_w<3>`.

Header, not all of it wired: RXD1 is MIDI IN 1, RXD2 is MIDI IN 2, RXD3 and RXD4 are wire-ORed to the uPD7810 TX line, and TXD1–4 are MIDI OUTs 1–4. This config has one MIDI in and one MIDI out.

## LED latches

Both latches invert the HC259 output (`q_out_cb<n>().set_output(...).invert()`).

`0x0000` `loledlatch`, bits 0–7: Edit Loop, Simul Seq, Transpose, Wait For, Count In, Auto Punch, Rec, Over Dub.

`0x0020` `hiledlatch`, bits 0–7: Play, Bank A, Bank B, Bank C, Bank D, Full Level, 16 Levels, After.

The header's LOLED × A1–A4 and HILED × A1–A4 lists name the same LEDs. It does not state this bit order. The bit order above is the `q_out_cb` index.

## Panel matrix

Header: PB0–PB3 drum-pad row select, PB4–PB7 column sense, AN0–AN3 column velocity, PC1–PC3 row select, PC4–PC5 encoder quadrature, PA0–PA7 column sense.

Code:

- `subcpu_pc_w` stores the key row as `((data ^ 0xff) >> 1) & 7`.
- `subcpu_pa_r` returns `Y[7 - row]`. Keys are `IP_ACTIVE_LOW`.
- `subcpu_pb_w` stores the drum row byte. `subcpu_pb_r` ORs `PB0`–`PB3` for each row whose bit `(3 - i)` is clear. Pad bits in the port defs are `0x10`, `0x20`, `0x40`, `0x80`, `IP_ACTIVE_HIGH`.
- `subcpu_pc_r` returns the data-entry quadrature on bits 4 and 5. The phase comment cites MPC2000 schematics and says a positive click rises PC4, then PC5, then falls PC4, then PC5. Negative is assumed to swap which bit rises first. The phase is doubled so the 7810 sees a change at most every second read. A 60 Hz timer integrates the dial.
- `an0_r`, `an1_r`, and `an2_r` return `0xFF`. `an4_r` returns the note-variation slider, but `an3_func` is set twice and the second call installs `an4_r`. `an4_func` is never set. Velocity is not modeled.

Key columns are active-low bits 0–7 of `Y0`–`Y7`. Empty positions are `IPT_UNUSED`.

| Row | bit 0 | bit 1 | bit 2 | bit 3 | bit 4 | bit 5 | bit 6 | bit 7 |
|---|---|---|---|---|---|---|---|---|
| Y0 | Pad Bank | Full Level | 7 | 8 | 9 | Disk | Program/Sounds | Mixer/Effects |
| Y1 | 16 Levels | Assign | 4 | 5 | 6 | MIDI | Song | Other |
| Y2 | After | unused | 1 | 2 | 3 | Seq Edit | Step Edit | Edit Loop |
| Y3 | Soft Key 1 | Soft Key 2 | 0 | . | Enter | Tempo/Sync | Transpose | Simul Seq |
| Y4 | Soft Key 3 | Soft Key 4 | unused | << | < | Auto Punch | Count In | Wait For |
| Y5 | unused (bits 0–1) | | − | + | Left | Up | Down | Right |
| Y6 | unused (bits 0–2) | | | Erase | Timing Correct | Tap Tempo | Main Screen | Help |
| Y7 | Stop | Play | Play Start | Rec | Over Dub | Locate | > | >> |

The header's Y4 `<` / `<<` order does not match the port bits. In the port defs, bit 3 is `<<` and bit 4 is `<`.

Drum pads, active-high:

|---|---|---|---|---|
| PB0 | Hihat Loose | Hihat Pedal | Floor Tom | Ride Bell |

## DSP routes

Left and right go to a stereo speaker. `OUT0`–`OUT7` go to eight outputs tagged `outputs`.

## Software lists

`mpc3000_flop` and `s1000_flop`. Floppy formats registered: DFI, MFM, TD0, IMD, DSK, PC, IPF, HFE.

## Device models pulled in by the includes

Taken from [MAME master](https://github.com/mamedev/mame/tree/master). These are the device implementations, not the Vailixi ROM. Generic includes with no MPC register map (`midi.h`, `nscsi/devices.h`, `floppy.h`, `i8255.h`, `pit8253.h`, `input_merger.h`, `nvram.h`, `timer.h`) are omitted. The two i8255 devices and the PIT have no port callbacks in `mpc3000()`.

Offsets below are the device's own map. Add the window base from the I/O table (`0x0060`, `0x00A0`, `0x00C0` / `0x00C8` / `0x00D0` / `0x00D8`, `0x00E0`, `0x00E8`).

### TE7774 — [`src/devices/machine/te7774.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/machine/te7774.cpp)

The file says the four channels are "i8251-shaped" and that **the register bits are complete guesses**. It also says the MPC3000 programs every channel for 31250 baud, 8N1, so the bit meanings cannot be derived from that init. `device_reset` forces 8 data bits, no parity, 1 stop bit, and 31250 baud regardless of what was written.

`read_cs` / `write_cs` use `offset & 3`, so each 8-byte chip-select window repeats a 4-byte register file.

| Offset | Read | Write |
|---|---|---|
| 0 | RX data. Sets status bit 1 and clears `rxrdy` | TX data, only if TX is enabled and the buffer is empty. Clears status bit 0 and clears `txrdy` |
| 1 | Status | Control 1. Bit 0 enables TX. Bit 2 enables RX. Other bits are stored and ignored |
| 2 | Control 2 | Control 2, stored only |
| 3 | Control 3 | Control 3, stored only |

Status bit 0 is `STATUS_TxRdy`. Status bit 1 is `STATUS_RxRdy`. On receive complete the model **clears** bit 1 and asserts `rxrdy`. On a data read it **sets** bit 1 and clears `rxrdy`. The comments next to those lines say the opposite of the operators. Transmit complete sets bit 0 and asserts `txrdy` when TX is enabled.

The same file records an init sequence it attributes to the MPC3000. Channels 0–3: control 1 gets `00 00 00 C0 02 95`, control 2 gets `00`, control 3 gets `04`. The last channel: control 1 gets `00 00 00 C0 02 91`, control 2 gets `00`, control 3 gets `00`. The comment treats the final channel as RX-disabled because the previous channel already covers that pin. That sequence is the author's note. The model does not decode `0xC0`, `0x95`, `0x91`, `0x02`, or `0x04`.

### uPD72069 — [`src/devices/machine/upd765.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/machine/upd765.cpp)

`upd72069_device` does not override `map`. It inherits `upd72065_device::map`:

| Device offset | Read | Write |
|---|---|---|
| 0 | main status (`msr_r`) | auxiliary command (`auxcmd_w`) |
| 1 | FIFO | FIFO |

`upd72069_device::auxcmd_w` handles, by comment:

- `0x36` software reset
- `xx 0x0E`–`0xFE` step `0x10`: motor enables. Motor `i` is bit `i+4`, active low on `mon_w`
- `xx 0x0B`–`0xFB` step `0x10`: internal mode. Top two bits select 250, 500, 600, or 300 kbit/s
- `0x88`–`0xF8` step `0x10`: data rate, marked 72069-only. Bits 6–4 select 250, 500, 600, 300, 1000, or 1250 kbit/s
- `0xC3`–`0xF3`: precompensation, marked 72069-only
- `0x4F` IBM format, `0x5F` ECMA/ISO format, `0x35` set standby

### L7A1045 / L6028 — [`src/devices/sound/l7a1045_l6028_dsp_a.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/sound/l7a1045_l6028_dsp_a.cpp)

The comment says the schematics call the chip L6028, QFP120, and that the same chip is in several Akai samplers plus the Hyper NeoGeo 64. Companion chips named there, and not instantiated by `mpc3000()`, are L6029 (DFL) and L6038 (DFX). The header credits Happy for the voice-register layout. Treat that layout as the model's decoding, not as a datasheet in this tree.

Device map, 16-bit ports, installed at `0x0060`:

| Offset | Access | Behavior in code |
|---|---|---|
| `0x0000–0x0001` | write | Voice select. Low byte, bits 4–0: channel 0–31. High byte, bits 3–0: register 0–15. Values above those ranges are logged and then masked |
| `0x0002–0x0007` | rw | Three 16-bit lanes of the selected 48-bit voice register. Lane `n` is bits `n*16` |
| `0x0008–0x0009` | rw | Control word |
| `0x000C–0x000D` | write | `atomic_w`: zeroes the selected voice register. The written data is logged and discarded |

Control bits the **code** tests: bit 6 starts the DMA timer (`64` ticks of the 33.8688 MHz clock, repeating); clearing bit 6 stops it. Bit 8 keys the current channel on (clears position and fraction, sets the key bit, recomputes loop start). The comment above `control_w` assigns more bits (0–4 DMA/record, 5 direction, 7 DMA complete, 15 busy). Those bits are stored in `m_control` and are not otherwise tested.

The block comment's register 4 "key on" bit is not what `control_w` implements. Key-on in the code is control bit 8.

Voice registers the switch actually applies:

| Reg | Enum | What a write updates |
|---|---|---|
| 0 | `L6028_Start` | Start address is bits 35–12 (`>> 12`, masked to 24 bits). Sample type is bits 39–36. A start write clears position, fraction, and filter state |
| 1 | `L6028_End` | End address is bits 35–12, then masked with `0x00fffff0`. Step is the low 16 bits |
| 2 | `L6028_Loop_Start` | Loop start, by the two encodings in the block comment |
| 3 | `L6028_Volume_Env` | Envelope volume is bits 31–16. A write of 0 to lane 0 clears that channel's key bit. Comment: "MPC3000 writes timed 0 to offset 0 to silence" |
| 4 | `L6028_Volume_Env_Target` | Target is bits 31–16. Step is the low 16 bits |
| 5 | `L6028_Filter_Env` | Cutoff is bits 31–16, copied only while `flt_pos` is 0 |
| 6 | `L6028_Filter_Env_Target` | Target is bits 31–20. Resonance is bits 19–16. Step is the low 16 bits |
| 7 | `L6028_Mixer_Params` | Right volume bits 7–0, left bits 15–8, send destination bits 23–16, send level bits 31–24 |

Sample type 0 is 16-bit little-endian from the data space. Sample type 1 is the 12-bit-in-8-bit expansion from the I/O space. `dma_r16_cb` / `dma_w16_cb` use voice 0's start and position. The block comment's routing table for register 7 (`0xf` = delay, and the 5,1,4,0,7,3,6,2 output order) is not applied by `voiceregs_w`; the code stores the destination byte as written. A separate `channel_remap[8] = { 3, 1, 7, 5, 2, 0, 6, 4 }` exists and is not used in the functions above.

### HC259 LED write — [`src/devices/machine/74259.cpp`](https://github.com/mamedev/mame/blob/master/src/devices/machine/74259.cpp)

`write_nibble_d3` ignores the port offset. The latch address is `data & 7`. The latched level is bit 3 of `data`. That is the bit order behind the `0x0000` and `0x0020` LED tables.
